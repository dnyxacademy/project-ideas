# Web development project ideas

Six briefs, all of them shaped to the same four stages:

| Stage | What the project becomes |
|---|---|
| 1 | A responsive static prototype, deployed |
| 2 | A typed React front end, with Tailwind |
| 3 | Next.js, an Express API and PostgreSQL |
| 4 | Sign-in, tests in CI, shipped, demoed |

**These are stages, not a schedule.** Take as long as each one needs — a stage might be a week
if you are on a taught programme, or a month if you are fitting this around a job. The order is
what matters.

So picking a brief is picking a **domain**, not a different amount of work. Each page lists its
minimum, a table sketch, a stage-by-stage shape, stretch goals, and the specific things that will
trip you up.

| Idea | Level |
|---|---|
| [Event RSVP and check-in](event-rsvp.md) | gentle |
| [Clinic appointment booking](clinic-appointment-booking.md) | comfortable |
| [Student marketplace](student-marketplace.md) | comfortable |
| [Shared expense tracker](expense-tracker.md) | comfortable |
| [Library management](library-management.md) | comfortable |
| [Fresher job board](job-board.md) | ambitious |

Every one of them needs **three related tables, validation, sign-in, eight tests with one
end-to-end flow, and a deployed front end and API** — that is one shared bar, not something each
brief invents. It is also a reasonable definition of done for a portfolio project.

Your own idea is welcome: [propose-your-own.md](../propose-your-own.md).
